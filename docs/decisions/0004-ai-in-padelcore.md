# 0004: AI decision logic lives in PadelCore

**Date:** 2026-11-15 · **Status:** proposed (Agent 4)

- **Where:** the AI's decisions (prediction, interception, pair tactics, shot choice, difficulty, partner commands) are plain C++ in `Source/PadelCore/{Public,Private}/AI/`, namespace `Padel::AI`. `Source/Padel/AI/` only holds engine glue: loading the data files and mapping the `IA_Cmd*` actions to commands. CLAUDE.md lists AI under `Padel/AI/`; the logic moved down so it is deterministic, headless and covered by the native tests that CI runs on every PR (GDD 8 determinism, GDD 12 soak). The folder is Agent 4's; no other PadelCore file was touched.
- **Ball model:** the AI predicts through `IAiBallModel`; `FAiEngineBallModel` wraps Agent 2's `FBallSim` (prediction passes no RNG, so the mesh's scatter is what the AI can't foresee). The test-only stand-in ball and match are gone.
- **Playing the real match:** `FAiMatchRunner` plays four players on `FMatchSimulation`. Every player, AI or human, moves and swings through Agent 3's `FPlayerShotController` (GDD 8: the AI plays through the same shot model as a human); the AI only produces a stick vector and `RequestAiShot`. `FAiMatchBallPort` is the shot system's `IBallPort` onto the match: prediction on the engine's integrator (one cached path shared by all four controllers each tick), rally shots to `PlayShot`, and the serve toss as a local ball whose contact goes to `PlayServe`, so the referee judges the bounce, waist and stance. `AiEngineBridge.h` is the one place AI and engine types meet. Two pieces of glue the AI needs on top of the shot model: the AI's shot waits until the controller has picked the same contact moment as the AI's plan, and a flat shot whose solved flight can't clear the tape is aimed deeper, then played at another pace, then lobbed. Gameplay's match game mode can own a runner and pass the human's input through `SetHumanInput`.
- **RNG:** the AI uses the match's shared `Padel::FPadelRng` (PadelRng.h). Each AI pair owns one seeded from the match seed; `AI/AiRandom.h` adds the weighted-choice helpers the AI needs. Every public AI class and function is exported with `PADELCORE_API` so the Padel module links against it in modular editor builds.
- **Data:** `Data/Difficulty.json` (the GDD 8 table) and `Data/AiTactics.json` (every other AI number). Both use the DataTable JSON layout. PadelCore reads them with a small strict reader (`AiTuningJson`): every field must be present and unknown keys are errors, so the data and the structs can't drift. `FDifficultyRow` mirrors the difficulty file for menus.
- **Soak:** `Ai.Soak` is a native test on the real match and shot system. CI runs 4 Medium one-set matches plus 2 Easy and 2 Hard ones; `PADEL_SOAK_MATCHES=100 Tools/RunNativeTests.sh -tc="Ai.Soak*"` runs the full 100. A `Padel.Soak` automation test can wrap the same runner in the engine later.
