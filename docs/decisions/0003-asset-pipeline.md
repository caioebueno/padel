# 0003: Asset pipeline

**Date:** 2026-11-15 · **Status:** proposed (Agent 5)

- **One catalogue, one command.** Every 3D asset is an entry in `Tools/AssetPipeline/config/assets.json` (id, kind, size in metres, triangle budget, LODs or Nanite). `python3 Tools/AssetPipeline/pipeline.py all` builds every asset in Blender, writes FBX files to `SourceArt/`, and imports them into `Content/Padel/` with Unreal Python. Material colours live in `config/palette.json`. The `.uasset` files are generated, like the input actions, so they're never edited by hand.
- **What's committed.** Procedural outputs (the FBX and PNG files the scripts build) are rebuilt by `build` in a few seconds, so git ignores them (`SourceArt/.gitignore`, written by the pipeline), and `all` always rebuilds before it imports. AI and hand-off models can't be rebuilt for free, so their cleaned FBX files are committed through Git LFS. `SourceArt/manifest.csv` is always committed.
- **Simple shapes are scripted, not generated.** The court, net, glass, ball and racket are built in Blender from `CourtSpec.h`, which the pipeline parses, so the art court and the collision court can't drift apart. AI generation is for organic shapes (people, props), where scripts are poor.
- **Characters.** The final athletes are MetaHumans (GDD 10). MetaHuman Creator is an interactive tool, so faces can't come from a script. For now there are two rigged placeholder athletes in the team kits, and an AI route (Meshy or Tripo, text to 3D, then the provider's auto-rig with the Unreal mannequin skeleton). All three use Unreal mannequin bone names, so mannequin and motion-matching animations retarget with the engine's IK Retargeter and no manual chain setup.
- **AI services.** Meshy is the default because it rigs straight onto the `ue5_mannequin` skeleton. Tripo is supported as a second provider. Keys come only from the environment (`MESHY_API_KEY`, `TRIPO_API_KEY`). Raw downloads stay out of git (`SourceArt/_raw/`). The manifest records the provider, the task IDs, a hash of the prompt and the date. Both services give paid plans ownership of the output but put free-plan output under CC BY 4.0, so the plan used must be checked before an asset ships.
- **Originality guard.** Prompts, negative prompts and asset IDs are checked against `config/blocklist.txt` (real tours, brands, players and games, matched without accents or case) before anything is sent. Every prompt also asks for no logos, text or likeness. This is a safety net: new names still get searched by hand.
- **Units.** Blender works in metres on Unreal's axes (X along the court, Z up). The FBX export converts to centimetres in one place (`bl_common.export_fbx`), with unit object scales and an armature object named `Armature`, so Unreal adds no extra root bone and no 100x scale.
- **Nanite for static meshes, baked LODs for skeletal meshes.** Glass is a separate non-Nanite mesh, because Nanite can't render translucent materials.
- **Blender** 4.2 LTS or newer (the app), or the `bpy` module from PyPI. CI uses `bpy` to build every procedural asset and check the exported FBX files on every PR.
